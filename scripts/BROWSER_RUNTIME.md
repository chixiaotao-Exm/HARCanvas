# 普通浏览器执行器

浏览器方块使用实际 Playwright 浏览器上下文。支持打开网页、点击、填写、读取文字、等待元素，以及在运行区人工接管。没有注入指纹伪装脚本、验证码求解器或网站验证绕过逻辑。

## 安装

在项目的 `scripts` 目录安装锁定依赖与浏览器：

```sh
npm ci
npx playwright install --with-deps chromium
```

服务器启动工作目录应为项目根目录。依赖要求 Node.js 20 或更新版本，需要在服务的 PATH 中，或设置 `HAR_CANVAS_BROWSER_NODE` 指向 Node.js。`HAR_CANVAS_BROWSER_WORKER` 可指定 `browser-worker.mjs` 的绝对路径。

默认只安装 Chromium。选择 Firefox 或 WebKit 前，需要分别执行 `npx playwright install --with-deps firefox` 或 `npx playwright install --with-deps webkit`；没有安装时，运行明确报告能力缺失。服务器用户需要有浏览器缓存目录的读取和执行权限。

## 实际能力与边界

- 每个会话有独立浏览器上下文、Cookie、本地存储和网页。浏览器结果返回实际语言、时区、User-Agent 和窗口尺寸。
- 普通 HTTP 方块与浏览器方块目前各自维护 Cookie，不能假定两种执行器自动交换登录状态。依赖网页登录的后续网页操作应继续使用同一个浏览器会话。
- 所有浏览器 HTTP(S) 连接经过 Go 内部代理，复用现有目标地址校验和具体 IP 拨号；外部 SOCKS5/HTTP/HTTPS 代理也经过这一层。代理失败不会回退直连。
- 一个浏览器上下文中的代理和画像固定。需要换环境时创建独立会话。画像中的 User-Agent 只影响支持的浏览器配置，不会变成另一套 TLS 或真实设备指纹。
- 人工接管显示真实 JPEG 画面，可点击、输入、按键、滚动、打开地址。完成后继续同一上下文，不重放已经完成的步骤。接管地址仅在当前等待阶段有效。
- 默认最多同时保留 4 个浏览器上下文。选择“下次运行继续使用这个会话”后，在同一个项目里保存当前服务进程内的上下文；空闲 30 分钟自动释放，服务重启后丢失。同一保存会话拒绝并发运行。循环中的“每轮新会话”仍使用独立临时会话。
- 弹窗和下载暂未开放：下载会被取消，新窗口会被关闭。网页需依赖这些能力时应调整步骤或扩展执行器，不能把失败当作已经完成。

## 验证

常规 Go 测试不要求安装浏览器。安装后，可启用真实浏览器验收：

```powershell
$env:HAR_CANVAS_BROWSER_TEST='1'
go test ./internal/app -run TestBrowser -count=1 -v
```

该测试只访问本机合成网页，验证实际画像、打开/点击/填写/读取、会话隔离、截图、人工接管、继续执行、保存会话并发限制、过期释放及守卫代理，不访问用户业务账户。

# 多 HAR、会话方块与 Agent 对话：阶段交付与验收审计

审计日期：2026-10-23。状态：A–F 阶段的主要代码已实现并通过相应自动化检查，G 阶段部分完成，尚未据此确认正式发布。

本文件保留原始需求设计，并在各节开头记录当前交付状态。需求中列出的验收目标不等于已经通过的验收结论；实际证据与未测限制见末尾的阶段表及验收记录。真实业务 HAR 重放、首次使用者验收、浏览器 UI P95、灰度与回滚仍不能据本文件判定通过。

## 目标与设计原则

让没有编程基础的用户，把不同网站的操作录制放入同一项目，用中文告诉 Agent 如何组合，在方块中填写业务参数，观察实际运行状态。继续采用现有 Go 服务、React/TypeScript 和 React Flow 画布。

默认使用情境是用户操作个人账户或已有团队资产。Agent 聚焦任务、缺失参数和技术限制，不反复要求用户证明用途或授权。普通编辑直接应用并允许撤销；分析、提问和编辑不自动执行网络流程。用户明确点击运行或在对话中明确要求执行，才启动相应运行。

保留现有体验：默认白色主题、可切换主题、匿名访问、刷新后空白工作台、主动导入项目、方块内输入、自动连线、运行定位。模型地址沿用以 `/v1` 为基础的兼容 API 配置，输入保持可见、显式保存。

## 当前实现基础

- 项目导出已升级到 v4，包含 `projectId`、多份 `captures`、节点、连线、填写值、项目默认资源、资源关联与可恢复的对话；v1–v3 旧项目有迁移路径。
- 新增 HAR 默认追加，保留已有流程。请求使用来源命名空间，同时保留 `captureId / originalRequestId`，各录制可以筛选、改名、重新导入与单独分析。
- 已实现固定次数、列表遍历、子流程和提前退出。每个流程内部仍按 DAG 校验，循环由结构化区域执行。
- 已实现代理、画像和具名会话资源。不同录制默认隔离，用户可指定项目、子流程或单个步骤使用的资源；配置虚线不参与执行拓扑。
- 运行历史已按 `executionId / scopePath / iteration` 区分每轮实例，支持查看对应结果、人工暂停、取消及恢复同一后台任务的状态查询。
- 已实现可收缩、可调宽的 Agent 对话与事务化画布命令；无效或过期编辑不会覆盖当前图，编辑可撤销与重做。
- 普通真实浏览器执行器已接入 Playwright，实际 Chromium 测试覆盖操作、截图、人工接管、会话隔离和回收。未接入 Sentinel challenge、PoW、`turnstile.dx` 或自动组装验证通过头。

这些判断来自当前工作树中的 `App.tsx`、`captures.ts`、`projectDocument.ts`、`graphCommands.ts`、`agentChat.ts`、`ResourceFields.tsx`、`execution_runtime.go`、`runtime_resources.go`、`browser_runtime.go`、`browser-worker.mjs` 及对应测试。实现检查与服务部署状态分别记录，不把工作树变更等同于已上线版本。

## 1. 多份 HAR 追加同一项目

**实现审计：已实现。** 已接入追加队列、录制列表、来源命名空间、单来源分析、局部生成、v4 迁移与导入导出。来源冲突、旧项目保持编号和嵌套来源等有自动化覆盖。重复文件内容识别、可移植的完整原始响应资料包属于后续设计，当前不承诺重复文件自动合并或大响应永久可恢复。

左侧改为“录制资料”，每份资料显示用户可改的名称、网站、时间、请求数量、解析/分析进度。主入口为“添加 HAR”；“新建项目”另设入口。导入后默认追加，允许主动选择替换当前项目。

在读取完成、分析过程中或排版之后，都可以继续添加资料。上传、解析和分析按来源分开管理；计算资源不足时排队，界面明确显示原因。取消或失败只影响该次导入。正在运行的流程使用既有快照，后续添加内容用于下一次运行。

新增资料放入独立画布区域，已有方块的位置、连线、填写值与手动修改保持稳定。补充分析只处理选定来源；用户删除的自动生成步骤不会因为另一份资料分析完成而重新出现。

数据模型升级为 `ProjectDocument v4 → captures[] → requests[]`。使用 `captureId + requestId` 标识录制请求，节点保留原始来源。分析、分组、缓存、生成去重、已删除标记、待确认依赖与迟到响应全部带来源及版本。相同 URL 的不同请求不直接去重；重复文件可提示复用或作为另一份录制导入。

旧版项目迁移成一份录制，保留旧节点编号、连线和填写值。导出后再导入应恢复全部来源与配置。临时响应地址不能当作永久资料：大响应缺失时显示“需要重新导入原 HAR”，后续增加可选的完整资料包导出。

跨网站组合面向用户展示为“把「获取订单」的订单编号，交给「查询物流」”。Agent 可以提出连接和数据绑定，但不能只因为字段同名或时间相邻就认定存在依赖。不同来源默认独立登录会话；用户可指定复用已有会话。Cookie 仍遵守域规则，不把网站 A 的 Cookie 直接交给网站 B。

## 2. 代理方块

**实现审计：已实现。** 方块可解析并编辑 SOCKS5/HTTP/HTTPS 连接、选择唯一会话片段、设置四种轮换方式、测试连接、关联执行范围及定位失败资源。URL 编码、IPv6、认证隧道、不回退直连、目标地址限制和轮换时钟有测试；真实 Chromium 经认证 HTTP CONNECT 与 SOCKS5 代理的受控联通也已验证。商业代理服务商实际换 IP 的效果、地区及计费行为未实测，用户名字段目前只作片段选择，不宣称已完成服务商专用适配。

用户粘贴代理 URL 后，方块显示可编辑的协议、地址、端口、用户名、密码；原始字符串同步保留并正确处理 URL 编码和特殊字符。首版代理协议以 SOCKS5、HTTP CONNECT 为目标，分别做实际连通性验证。

用户名再显示为可点击片段。对于已适配的服务商格式，可以识别地区、会话标识等字段；用户点击会话标识即可选择：

- 固定值。
- 每次流程运行生成。
- 每个请求生成。
- 每 X 分钟轮换。

用户名中的 `sid`、`region`、`t` 等属于服务商约定，不能作为通用 SOCKS5 语法。未识别的服务商提供“选中这一段作为会话标识”，只替换明确选中的片段；`t` 的含义由适配规则说明，不擅自解释。

方块明确显示“应用于整个流程 / 某个子流程 / 选定请求”。代理是配置资源，通过配置关系关联执行范围；不因多画一条线就混淆执行顺序。普通请求默认继承所在会话的代理，也允许显式覆盖并在预检中检查兼容性。

配置关系单独存为 `resourceBindings`，在画布上以区别于执行线的样式显示，不计入执行入口、可达性、拓扑顺序或循环判断。默认继承优先级为请求显式配置 → 最近子流程配置 → 会话配置 → 项目默认；浏览器已固定的代理不允许被单个浏览器步骤中途覆盖，预检要求创建新会话或统一配置。导入后资源或凭据缺失时标记待补充，不静默直连或共用默认会话。

每 X 分钟使用运行时钟计算，轮换在下一次请求开始时生效，不打断已发出的请求。每请求模式对应请求级传输，处理连接池和重定向的一致性。同一逻辑请求的重定向默认使用同一会话标识；其他语义必须显式设置。更换会话标识不保证服务商实际更换出口 IP。

涉及登录或浏览器会话时默认在整个会话内固定出口。用户选择请求级轮换且与会话固定设置冲突时，预检指出具体冲突并提供调整入口。代理失败直接定位代理方块，不静默回退直连。方块提供用户主动点击的“测试连接”，输出耗时和出口信息。

实现前验证 HTTP 执行器与浏览器执行器各自支持的认证方式；不能把 Go 请求支持某种代理等同于浏览器也支持。保留现有目的地址与重定向校验，明确代理侧 DNS 的处理方式，防止代理路径使已有地址限制失效。

## 3. 浏览器验证与人工接管方块

**实现审计：真实浏览器操作与人工接管已实现。** 浏览器方块支持打开、点击、填写、读取、等待；人工接管显示实际 JPEG 画面，并支持点击、文字、按键、滚动和打开地址，继续后保留同一上下文。接管标识仅在当前等待期间有效，工作进程也校验当前接管令牌。实际 Chromium 自动化测试已通过；官方站点验证接口属于后续单独集成，Firefox/WebKit 与第三方真实验证成功率未在本轮证明。

用户提出的查找并集成自动求解 Sentinel challenge、PoW、执行 `turnstile.dx` 和组装通过验证的 Sentinel 头，涉及绕过网站反自动化验证，不纳入实现。本轮没有为查找这类模块连接所提供服务器，也不将服务器口令写入项目。

替代为常驻的“打开浏览器完成验证”方块：使用受支持的真实浏览器会话，在需要用户操作时暂停，用户完成网站正常验证后继续。复用同一上下文，不重放已经完成的业务步骤；代理或会话发生冲突时明确提示。人工完成验证不保证后续接口接受脱离浏览器的 HTTP 重放，依赖浏览器的后续步骤继续在该会话内执行。

对于用户自有站点，可按官方验证接口接入正常验证流程。当前已交付人工暂停/继续、能力标记及远程浏览器可视化与接管；官方验证接口仍按具体站点独立接入，不能提前将不支持的步骤标为已就绪。

## 4. 会话一致性方块

**实现审计：已实现支持范围内的一致性。** 具名会话关联固定代理与画像，可在项目中设为默认；虚线与说明展示引用关系。HTTP 与浏览器分别保留 Cookie，不自动互相同步。显式保存会话仅存在于当前服务进程，空闲 30 分钟释放，重启后丢失，并拒绝并发占用；临时新轮次会话在每轮结束后释放，已修复顺序循环累积占满浏览器容量的问题。会话隔离、保存/过期、配置冲突、worker 崩溃回收均有回归测试。

界面名称建议为“保持浏览器环境”，技术类型为 `browserSession`。方块让用户选择一个具名会话，并连接代理、画像及需要使用该会话的步骤。

运行时该资源统一管理 Cookie、浏览器上下文、语言、时区、视口、代理引用与画像版本。默认本次流程固定；重新运行时可选择新会话或显式复用已保存会话。HTTP 请求与浏览器步骤共享哪些状态要写入契约，只同步支持的状态，不能承诺所有浏览器存储都能转换成请求头。

运行开始固定资源快照。用户调整画像或代理不改变正在运行的上下文；需要变更时在明确边界创建新会话。多 HAR、多账号和并行子流程均通过不同会话隔离。界面显示“正在使用哪个会话、代理、画像”，帮助新手理解为何某些设置不能中途改变。

“一致性”指支持的配置与真实执行上下文保持一致，不承诺伪装成任意设备或保证通过网站检测。

## 5. 指纹画像方块

**实现审计：已实现实际配置能力。** 画像提供 Chromium/Firefox/WebKit 选项、语言、时区、窗口和可选 User-Agent，可读取当前页面的语言/时区/窗口，或从其他画像复制；浏览器步骤返回实际应用值。当前页面环境读取不会复制本地浏览器内核、硬件、TLS 或 WebGL 身份。HTTP 仅应用支持的请求头。用户附件已审阅，未将其中任意画像字符串当作实际设备能力接入。

界面提供“使用当前浏览器环境”“保存的画像”“自定义测试环境”，普通模式只显示浏览器、语言、时区、窗口尺寸等易懂字段；高级字段展开查看。

已阅读用户提供的 `fingerprint.go`、`herocore_profile.go`、`go.mod` 和 README。这两个 Go 文件包含 `BrowserProfile`、稳定画像选择及请求头生成逻辑；仅依赖标准库，不会启动真实浏览器，也没有 TLS/HTTP2 传输实现。`Impersonate` 在这些文件中只是名称，国家参数也不表示真实出口位置。现有版本池和硬件字符串需要适配与验证，不能原样作为真实性保证。

候选复用范围：画像结构、稳定标识、语言/时区映射和配置摘要。画像应存储实际参数与版本，避免代码升级后同一个标识悄悄变成另一套环境；时区偏移按时区规则和实际时间计算，不固化夏令时偏移。

方块分别标记“配置值”“执行器实际应用值”“无法应用的值”。真实浏览器用支持的配置能力并通过自有回显页验证；普通 Go HTTP 模式只声明实际设置的请求头等能力，不将其描述成完整浏览器指纹。首版不增加隐藏自动化特征或反检测补丁。

画像方块描述环境，会话方块让一组步骤持续使用该环境。两者独立可复用；新手可通过“创建固定浏览器环境”一次生成并关联它们。

## 6. 新方块流畅性与联合验证

**实现审计：功能回归已建立，流畅性验收尚未全部完成。** 已加入离线入门练习、跨来源取值→条件→列表循环的合成运行测试，以及 200 节点/300 连线和 1000 节点/1498 连线的纯函数基线。基线测试的 Node.js 耗时不代表真实浏览器拖拽、输入、绘制或 UI P95；下面的验收矩阵继续作为发布关口，不应整表标记完成。

新增节点统一遵循：中文用途、就地输入、明确作用范围、输入输出、配置检查、真实运行状态、失败定位、导出导入和撤销支持。配置完整只表示“可检查”，不能直接显示“运行成功”。

建立自有模拟站点和测试代理，采用“网站 A 获取业务编号 → 网站 B 查询该编号 → 条件判断 → 重复处理 → 输出结果”作为贯穿验收，不需要用户真实账户，也不调用实际注册接口。

验收矩阵：

| 范围 | 必须通过的场景 |
| --- | --- |
| 多 HAR | A 已分析排版并填写后追加 B；A 保持不变；B 取消、失败和迟到响应不影响 A |
| 来源隔离 | 两份录制都有 req-1、同名分组和同名字段，仍能正确溯源和绑定 |
| 代理 | URL 解析还原、特殊字符、认证失败、手动测试、固定/按次/按时轮换、不回退直连 |
| 会话与画像 | 同会话配置稳定、不同账号不串 Cookie、实际应用值可验证、不支持项可定位 |
| Agent | 收缩保留对话与输入；旧回复不覆盖新图；无效命令整批不落地；可撤销重做 |
| 循环 | 0/1/多次、部分区域、条件分支、嵌套、暂停继续、取消、断线恢复、不重复已完成请求 |
| 新手交互 | 不写 JSON 路径即可接通两个网站；输入 Delete 不删除方块；全屏、聊天和菜单互不遮挡 |
| 项目兼容 | 旧项目迁移、v4 导出再导入，来源、连线、填写值和资源引用保持一致 |

性能用固定浏览器、设备与合成资料建立基线，记录 200 节点/300 连线和 1000 节点场景。建议发布目标：200 节点常用编辑的输入反馈 P95 小于 100ms；开始分析或运行后 1 秒内出现本地已提交/排队反馈；取消后立即显示取消中，并通过服务端事件确认完成。它们是待测目标，不是现有性能结论。HAR 读取、解析和模型调用分别显示真实进度与耗时，未知剩余时间时不显示伪造百分比。

## 7. 微信式可收缩 Agent 对话

**实现审计：主体已实现。** 已有消息布局、折叠/展开、草稿保留、宽度拖动、停止/重新发送、模型设置入口、选区引用、定位按钮、对话内多输入框与共享填写值。当前问题组件以文本输入为主；选择型问题和更细的录制范围引用仍需按实际产品需求补齐。对话可随主动导出的项目恢复，刷新仍从空白工作台开始；重新发送对话不自动重放业务请求。

右侧提供常驻聊天面板：用户消息靠右、Agent 靠左、底部输入，支持停止、重试、折叠、展开与宽度调整。收缩后显示悬浮入口及“正在分析 / 等待填写”等状态，未完成输入保留。模型设置放在聊天顶部的设置入口。

对话可引用当前选中方块、多选区域、某份 HAR 或整个项目。引用用中文步骤名称显示，点击定位画布；没有选中时默认项目范围。示例：“把订单编号传到物流查询”“这几个步骤重复 5 次”“这里使用已有代理”。

Agent 的补充问题作为消息内表单，包含多个输入框、选择项与示例，不使用弹窗。聊天、方块和运行区共用字段值与校验，填写一次后同步。

分析与运行消息显示真实阶段、耗时、创建/修改的步骤摘要和可点击修复入口。聊天重试不能隐式重试业务请求。刷新后仍不自动打开历史项目；当前对话可随用户主动导出的项目恢复，API Key 不混入项目文件。

## 8. Agent 操作所有已支持方块

**实现审计：已实现注册类型的结构化编辑。** 统一命令支持创建、修改、复制、删除、连线、断线、绑定、移动、排版、分组、资源关联和循环/子流程封装，能编辑嵌套范围。事务在实时画布上重新校验，版本或结构变化会拒绝过期回复，复制会改写内部依赖与输入键。Agent 可创建现有执行类型及复合流程；新增任意执行原语、任意生成代码运行不在当前能力中。

先建立统一节点能力目录与画布命令层。所有节点类型声明中文用途、输入、输出、字段约束、连线规则、资源作用范围、可执行能力和版本。用户手工操作与 Agent 调用同一套规则。

结构化工具覆盖：查看项目与选区、查看来源、创建/编辑/复制/删除节点、创建/删除连线、绑定输入、配置代理/画像/会话、建立子流程或循环区域、排版、预检、解释错误、撤销与重做。Agent 不需要用户提供节点编号。

每次 Agent 修改形成一个事务：携带项目版本和目标范围，先校验全部命令再一次应用；失败不留下半成品，过期结果不能覆盖新编辑。普通可逆编辑直接应用，提供“已修改 3 个步骤，可撤销”。连续输入和拖动合并为合理的撤销记录。

“创建新方块”分为创建已有类型、将多个步骤封装成具名可复用方块，以及新增执行原语。前两项由 Agent 操作；新执行原语需要注册字段协议和执行器并通过测试，不能只靠模型生成一个名称就宣称能运行。首版不在聊天中执行模型任意生成的 Go、Rust 或 Shell 代码。

Agent 对代理凭据和登录状态使用资源引用；模型只获得完成编辑所需的能力与结构。HAR、网页响应和附件内容作为资料，不作为授权 Agent 改项目或执行任务的指令。运行仍使用快照；分析、修补、聊天任务与业务执行分开取消。

## 9. 重复、遍历和条件方块

**实现审计：固定次数、列表遍历、提前退出与有限嵌套已实现。** 已有整体/局部封装、内部编辑、条件分支、每轮共享或新会话、显式失败后继续、逐实例历史与具体轮次定位。自动化覆盖 0/1/多次、嵌套作用域、分支值缺失、人工等待/取消/恢复和 fresh scope 回收。当前上限为每循环 1000 次、4 层嵌套、单次运行 10000 步，并保留响应与时间预算；“直到满足条件”仍为后续设计。

用户看到“重复 X 次”“逐项处理列表”“如果满足条件”，不需要写 `for` 或 `if/else`。已有条件方块升级为中文字段选择和是/否出口。

整体循环通过“重复整个流程”建立外层区域；局部循环通过框选后“重复这部分”建立。两者共用结构化子流程，内部仍按 DAG 校验，不使用随意向前回连的线模拟循环。画布不会复制成 X 份。

当前已包含固定次数、条件分支、局部区域、列表遍历、提前退出和有限嵌套。以后再评估“直到条件满足”，其超时与最大次数始终可见。

默认顺序执行；支持指定每轮继续同一会话或使用新会话。变量分为项目、子流程和当前轮次；每轮结果单独保留并可汇总。失败时默认停止并定位“第几轮的哪个步骤”；“记录后继续下一轮”作为显式策略。

运行事件增加 `executionId / scopePath / iteration`，历史结果使用执行实例标识，不再只以 `nodeId` 覆盖。人工暂停和断线恢复回到同一实例，不重新发送已完成请求。条件汇合需要确认当前分支确实产生了所绑定的值。

当前执行器已有节点数量和响应总量等预算。循环改造新增总步数、次数、累计响应、耗时与嵌套预算，面向用户显示具体上限和拆分方法，不简单删除现有限制。

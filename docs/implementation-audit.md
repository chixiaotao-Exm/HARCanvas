# Implementation audit — 2026-10-23

This audit covers the implementation against `docs/product-plan.md`. The review agent used synthetic fixtures, inspected no real HAR or user credentials, and replayed no external target. Root's browser acceptance is recorded below; deployment verification is recorded separately after publication.

## Verified

- `web/src/agentJobs.ts` starts each model task once, snapshots optional analysis context, and never retries POST. A terminal model failure no longer reports the successful poll's HTTP 200 as its error status.
- Once a job ID is known, poll/network/protocol failures attempt an independent DELETE. The original failure remains the diagnosis; an unresponsive DELETE stops waiting after 2.5 seconds. Completed/failed/cancelled terminal tasks are not redundantly cancelled.
- `node --test web/test/agentJobs.test.mjs`: 19 passing tests, including cancellation, cleanup failure/deadline, malformed responses, configuration/context snapshots and logging boundaries.
- `node scripts/smoke-runtime.mjs`: passed against an isolated Go API process and local synthetic model/HTTP servers. The model actually waits 21.5 seconds; there is one provider call, no HAR replay during import/analysis, structured source validation, manual pause/resume, assertion success/failure, skipped successors, HTTP 503 failure and explicit status acceptance, and ordered runtime events. Added real HTTP regressions for quotes/newlines/Unicode and query separators in bound JSON/query values, validation and execution of a dynamic HTTP base URL, and a generated-and-compiled upstream binding that sends the fresh runtime ID instead of the different recorded ID.
- Cross-capture request-ID collisions in generation were reported and corrected by the generation owner. A synthetic old/new capture with the same `req-1` now keeps the old node and adds the new node.
- `node --test web/test/analysisContext.test.mjs web/test/generation.test.mjs web/test/agentBatches.test.mjs`: 23 passing tests across these files after automatic binding coverage was added. Context budgeting applies to complete UTF-8 JSON and refreshed per-batch history, with a 480 KiB limit, bounded provenance fields, recent-history priority and visible truncation warnings. This does not rewrite HAR data or retained model results.
- Generation now allocates a column per business group, appends later children below the group's existing positions, preserves manual layout, and resolves node/edge ID collisions without silently dropping requests. Captured session/dynamic fields cannot be marked ready solely by a model's claim.
- `go test ./internal/app -run 'TestUpload|TestRejectedUpload' -count=1`: passed. Rejected oversized previews neither retain their full capture nor evict existing usable uploads. Store accounting includes header/URL/provenance content, and a single over-budget item is rejected before eviction.
- Reliable field relations initialize upstream parameter drafts on newly generated nodes for supported JSON string fields, single query values and exact raw header values. Deleted or edited bindings stay untouched on reanalysis. Prefix-sensitive Authorization values, form encodings, repeated queries, unsafe JSON numbers and unavailable sources remain pending/missing-input rather than receiving an incorrect binding.
- `npm run build`: passed after the context/generation/automatic-binding changes. Vite reports the existing advisory for the main chunk being over 500 kB.

## Backend runtime findings resolved

The following findings have landed locally and are covered by Go regressions; they do not replace the UI acceptance below.

- **B1 resolved:** JSON bodies that parse as JSON render string values recursively and marshal afterwards, preserving existing numeric/boolean types while escaping quotes and line breaks. Query placeholders are decoded, rendered as individual values, and encoded once, including upstream response values and encoded placeholders. URLs/bodies without templates retain their original bytes. Aggregate substitution expansion is bounded. `TestRequestBindingsEscapeJSONAndURLQueryValues` covers quotes, newlines, `&`, `=`, `+`, nested values and a large integer; `TestRequestRenderingRetainsUntemplatedSignedURLAndLimitsExpansion` covers signed URL byte preservation, encoded query placeholders, missing-variable preflight and expansion limits.
- **V1 resolved:** dynamic base/whole-address templates such as `{{base}}/path` pass preflight when their reference is valid; the fully rendered URL still passes the existing runtime NetworkGuard. `TestPreflightTemplatesBindingsAndRuntimePriority` exercises both validation and execution.
- **V2 resolved:** preflight now checks available input/produced variables before node results, agreeing with runtime resolution. The same regression includes a variable named like a request node.
- **L1 resolved:** execution events and terminal polling summaries use safe messages for generic transport/template failures. Full technical errors remain in the explicitly requested node/full-result endpoints. `TestFlowEventsUseSafeMessagesWhileDetailsRemainAvailable` checks that a private URL query value is absent from events/poll metadata and remains available in requested detail.
- **Agent error privacy resolved:** `AnalysisError` classifies analysis failures using controlled messages and stable `errorCode` fields shared by synchronous failures and asynchronous job polling. Provider-controlled request/dependency IDs, missing-description identifiers, JSON parser details, provider error bodies, and transport/read errors cannot echo HAR values into errors. `TestAgentErrorsAreTypedAndNeverEchoProviderValuesAcrossAPIs` covers nine synthetic failures through the direct analyzer, synchronous API, and asynchronous worker/poll API. The targeted Agent/context tests and `go vet ./internal/app` passed; timeout and cancellation messages retain their prior behavior.
- The runtime backend now implements immutable execution snapshots, explicit entry/reachability, structured Chinese preflight, ordered incremental events, cancellation, manual pause/resume within the same cookie session, HTTP-status failure/allowance and separate business assertions. Tests cover genuine blocked request events, create-request disconnection, session preservation without replay, late-response cancellation, active-slot retention, TTL/capacity, panic handling and HTTP method/sequence boundaries.
- `go test ./... -timeout 45s` and `go vet ./...` passed after the runtime changes. Race instrumentation is unavailable in this local Go environment (`CGO_ENABLED=0`); the tests use deterministic request barriers and atomic counters for concurrent scenarios. The independent local HTTP smoke run is recorded above by the review agent.

`API_CONTRACT.md` documents the final task endpoints, metadata-only polling, detail reads, analysis context, large HAR upload/detail retention and all runtime limits. The canvas limit is 3,000 nodes/5,000 edges; each selected entry can reach at most 100 nodes/300 edges, so a large imported capture can be divided into separate executions.

The additional frontend/runtime contract audit corrected binding-ID normalization collisions and overlong IDs; literal `{{...}}` in fixed values; conflicting writes that depended on binding array order; fixed numeric/boolean conversion; and unsupported dynamic scalar conversion. Generated IDs are deterministic and bounded, with explicit collision issues. Whole URL plus query bindings, whole body plus field bindings, and duplicate targets block rather than silently overwriting each other. Unsafe JSON integer edits are blocked rather than rounded. Dynamic numeric/boolean field bindings remain an explicit supported-scope limitation and require fixed values or full-body advanced editing.

`web/test/bindings-runtime.test.mjs` contains eight integration checks against an isolated Go API with a synthetic transport and the production NetworkGuard. They cover two generated manual steps before a single request, root/branch rewiring, condition handles, same-task resumes, cookie preservation, deleted sources, required values, typed fields, JSON/query/header special characters, fixed literal braces, identifier collision/length boundaries, temporary-node execution limits and original-node error mapping, cancellation and cursor polling. `web/test/runJobs.test.mjs` adds five client protocol checks for same-ID/ordered cursor polling, malformed views, abort/disconnection without replay, explicit DELETE cancellation, and structured POST failures without retries. No real HAR or external replay target is involved.

The final combined run passed: `npm test` (81 tests), `go test ./... -timeout 60s`, `go vet ./...`, and `npm run build`. The extended `node scripts/smoke-runtime.mjs` also passed, including the real 21.5-second model delay, actual local HTTP special-character rendering, dynamic-base destination guarding, and generated upstream bindings carrying current response values instead of recorded HAR values. The frontend build reports only its bundle-size advisory above 500 KiB.

## Local browser acceptance

The root agent performed the following browser checks against the local built UI. These are local verification results, not deployment certification.

- A fresh page on local port 8093 opens in light mode with zero nodes and zero records. Switching to dark, refreshing, and switching back to light preserves the selected theme. Refreshing does not restore a HAR or graph.
- An explicit browser upload of the actual approximately 123.3 MiB `re.har` produces 1,426 valid requests and zero generated nodes before analysis; a refresh returns to zero records and zero nodes. The review agent did not inspect that capture's contents.
- In the no-network practice, incorrect manual input causes an assertion error and skipped successors. A new run pauses for manual input and resumes the same job to successful output when given the expected value.
- An extraction block without a source produces three structured preflight issues; selecting `source_required` opens the correct node and focuses its source SELECT.
- The three-request synthetic HAR on local port 8094 analyzes into three design nodes and two evidence-backed edges. Editing a node name and its ticket upstream binding, then analyzing again, preserves those edits.
- After a fresh analysis using the final build, the second request automatically shows its query-credential upstream parameter with source request 1, path `body.ticket` and JSON target `ticket`. The browser verified the exact generated draft, in addition to the independent smoke's current-value HTTP execution.
- The in-process four-second synthetic HTTP request displays actual green `runtime-running` state and elapsed seconds, then success. Changing its URL to `/fail` produces HTTP 503, a red error node and skipped successors.
- Invalid header JSON survives a switch through the Agent tab, blocks preflight, and its issue opens and focuses the header textarea.
- The business-group wrapper stays visible during execution. Cancelling the third request yields child states success/success/cancelled, retains a visible `runtime-cancelled` wrapper, and collapsing displays the cancelled group with all three executed/attempted children accounted for.

The UI owner corrected lost wrapper measurements and added two regressions; the root agent re-verified the measured view and automatic parameter drafts in the final local build. Response detail reads now abort and reject stale success/error/finally callbacks by identity and generation, with two regressions. Model errors use controlled application messages and error codes rather than echoing provider-controlled identifiers, parser or transport text; synthetic direct/synchronous/asynchronous regressions pass. No pending code findings remain in this audit. Deployment and any real-model verification remain the root agent's responsibility.

The runtime smoke script is intentionally self-contained. It creates temporary files under ignored `test-results/`, injects DNS/dial behavior only in its test harness, leaves the production NetworkGuard unchanged, and removes its own process and files on exit.

A separate ignored `.deployment/ui-harness/` fixture serves the built UI at local port 8094, a compatible synthetic model at port 38997, and a three-request synthetic HAR with two evidence-backed dependencies. Every synthetic target waits four seconds; a path containing `fail` returns HTTP 503. Its runner accepts only `ui-harness.invalid` and uses an in-process response transport, so these browser checks cannot send captured requests to an external site. This harness is for local UI acceptance, not deployment.

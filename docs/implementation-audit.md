## Agent repair backend and client protocol — 2026-10-23

The repair implementation adds a third asynchronous Agent mode with an independent `repair` result. It shares the existing guarded provider transport, progress observer, concurrency slots, cancellation and retention. The value-free input catalog carries only node explanations, short issue codes, existing string-field locations and opaque source capabilities; unknown incoming value/body/header/URL properties are dropped during reconstruction. Model results reject unknown properties and cannot change readiness, overwrite existing bindings, select an unknown field/source, attach drafts to unsupported nodes, or omit explanations for nonready nodes.

## Backend runtime findings resolved

The following findings have landed locally and are covered by Go regressions; they do not replace the UI acceptance below.

- **B1 resolved:** JSON bodies that parse as JSON render string values recursively and marshal afterwards, preserving existing numeric/boolean types while escaping quotes and line breaks. Query placeholders are decoded, rendered as individual values, and encoded once, including upstream response values and encoded placeholders. URLs/bodies without templates retain their original bytes. Aggregate substitution expansion is bounded. `TestRequestBindingsEscapeJSONAndURLQueryValues` covers quotes, newlines, `&`, `=`, `+`, nested values and a large integer; `TestRequestRenderingRetainsUntemplatedSignedURLAndLimitsExpansion` covers signed URL byte preservation, encoded query placeholders, missing-variable preflight and expansion limits.
- **V1 resolved:** dynamic base/whole-address templates such as `{{base}}/path` pass preflight when their reference is valid; the fully rendered URL still passes the existing runtime NetworkGuard. `TestPreflightTemplatesBindingsAndRuntimePriority` exercises both validation and execution.
- **V2 resolved:** preflight now checks available input/produced variables before node results, agreeing with runtime resolution. The same regression includes a variable named like a request node.
- **L1 resolved:** execution events and terminal polling summaries use safe messages for generic transport/template failures. Full technical errors remain in the explicitly requested node/full-result endpoints. `TestFlowEventsUseSafeMessagesWhileDetailsRemainAvailable` checks that a private URL query value is absent from events/poll metadata and remains available in requested detail.
- **Agent error privacy resolved:** `AnalysisError` classifies analysis failures using controlled messages and stable `errorCode` fields shared by synchronous failures and asynchronous job polling. Provider-controlled request/dependency IDs, missing-description identifiers, JSON parser details, provider error bodies, and transport/read errors cannot echo HAR values into errors. `TestAgentErrorsAreTypedAndNeverEchoProviderValuesAcrossAPIs` covers nine synthetic failures through the direct analyzer, synchronous API, and asynchronous worker/poll API. The targeted Agent/context tests and `go vet ./internal/app` passed; timeout and cancellation messages retain their prior behavior.
- The runtime backend now implements immutable execution snapshots, explicit entry/reachability, structured Chinese preflight, ordered incremental events, cancellation, manual pause/resume within the same cookie session, HTTP-status failure/allowance and separate business assertions. Tests cover genuine blocked request events, create-request disconnection, session preservation without replay, late-response cancellation, active-slot retention, TTL/capacity, panic handling and HTTP method/sequence boundaries.
- `go test ./... -timeout 45s` and `go vet ./...` passed after the runtime changes. Race instrumentation is unavailable in this local Go environment (`CGO_ENABLED=0`); the tests use deterministic request barriers and atomic counters for concurrent scenarios. The independent local HTTP smoke run is recorded above by the review agent.

`API_CONTRACT.md` documents the final task endpoints, metadata-only polling, detail reads, analysis context, large HAR upload/detail retention and all runtime limits. The canvas limit is 3,000 nodes/5,000 edges; each selected entry can reach at most 100 nodes/300 edges, so a large imported capture can be divided into separate executions.

The additional frontend/runtime contract audit corrected binding-ID normalization collisions and overlong IDs; literal `{{...}}` in fixed values; conflicting writes that depended on binding array order; fixed numeric/boolean conversion; and unsupported dynamic scalar conversion. Generated IDs are deterministic and bounded, with explicit collision issues. Whole URL plus query bindings, whole body plus field bindings, and duplicate targets block rather than silently overwriting each other. Unsafe JSON integer edits are blocked rather than rounded. Dynamic numeric/boolean field bindings remain an explicit supported-scope limitation and require fixed values or full-body advanced editing.

`web/test/bindings-runtime.test.mjs` contains eight integration checks against an isolated Go API with a synthetic transport and the production NetworkGuard. They cover two generated manual steps before a single request, root/branch rewiring, condition handles, same-task resumes, cookie preservation, deleted sources, required values, typed fields, JSON/query/header special characters, fixed literal braces, identifier collision/length boundaries, temporary-node execution limits and original-node error mapping, cancellation and cursor polling. `web/test/runJobs.test.mjs` adds five client protocol checks for same-ID/ordered cursor polling, malformed views, abort/disconnection without replay, explicit DELETE cancellation, and structured POST failures without retries. No real HAR or external replay target is involved.

The final combined run passed: `npm test` (81 tests), `go test ./... -timeout 60s`, `go vet ./...`, and `npm run build`. The extended `node scripts/smoke-runtime.mjs` also passed, including the real 21.5-second model delay, actual local HTTP special-character rendering, dynamic-base destination guarding, and generated upstream bindings carrying current response values instead of recorded HAR values.

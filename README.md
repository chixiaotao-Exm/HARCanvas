# HAR Canvas

把 HAR 请求记录整理成可拖动、可编辑、可调试的流程。Agent 解释请求、归纳业务步骤并自动生成可编辑的画布；用户检查参数、调整连接并决定何时执行。

## 从多个网站组合一个流程

1. 点击「添加 HAR」导入第一份录制，说明目标并分析。已经生成的方块可以直接填写业务资料、改名、拖动和连线。
2. 再点「添加 HAR」加入第二个网站的录制。它会成为独立资料，保留第一份资料的方块、排版和填写内容；左侧切换资料后可以分别分析。每份录制默认使用独立会话。
3. 把网站 A 的业务结果交给网站 B：在 B 的「业务参数」中选择「使用上一步响应」，选择 A 的步骤和响应字段，再连接执行顺序。两份录制里的 `req-1` 不会混在一起。Agent 也可以帮助建立绑定，来源证据不足时会留下待补充字段。
4. 要使用代理，添加「代理连接」方块并粘贴链接。点击账号中的会话片段，选择固定、每次运行随机、每次请求随机或每 X 分钟轮换，然后主动点「测试连接」。只有选中的唯一片段会变化；服务商是否实际换出口，以连接测试和服务商规则为准。
5. 添加「保持浏览器环境」，选择代理与「浏览器画像」，再在需要的步骤里选这个会话。配置关系显示为虚线，执行顺序仍看普通连线。登录会话通常使用固定环境；有冲突时预检会指出具体方块。
6. 框选步骤后可封装为子流程或循环，也可添加「重复步骤」并打开内部画布。次数为 0 时跳过内部流程；列表遍历逐项执行；条件用「是 / 否」连到不同后续步骤。每轮的结果和人工暂停分别保留。
7. 打开右侧 Agent 对话，用中文提出「把这些步骤重复两次」「这里使用已有代理」等要求。对话可以收起，待填写问题直接显示在消息里。可逆编辑通过统一事务应用，可撤销；对话和分析不会自动运行业务流程。
8. 主动运行后，绿色边框显示当前步骤，失败定位到步骤及轮次。导出项目保存资料、连线、参数、画像和对话；刷新仍打开空白工作台，需要主动打开项目恢复。

不想先准备 HAR，可以主动打开无网络练习：基础练习体验输入与人工暂停；扩展练习体验条件、两轮重复、每轮填写与提前结束，不需要模型 API。

## 浏览器画像实际会做什么

画像方块保存 Chromium / Firefox / WebKit、语言、时区、窗口和可选 User-Agent。可以读取当前网页的语言、时区与窗口，或从已有画像复制配置；导出项目即可保存。当前网页的设置是配置起点，实际运行使用服务器已安装的浏览器。

| 项目 | 实际能力 |
| --- | --- |
| 浏览器步骤 | 使用真实 Playwright 上下文应用支持的参数；运行结果返回实际语言、时区、窗口、User-Agent |
| 普通 HTTP 步骤 | 应用支持的 `User-Agent`、`Accept-Language` 请求头；不会应用屏幕、窗口、CPU、WebGL 或改变 TLS/HTTP2 指纹 |
| 同一会话 | 同类步骤共用 Cookie / 浏览器上下文；代理与画像在运行期间固定。HTTP 与浏览器目前各自保留 Cookie，不自动交换登录状态 |
| 显式保存会话 | 保留在当前服务器进程内，空闲 30 分钟后释放；重启后丢失。同一保存会话不允许同时被多个运行使用 |
| 人工网页操作 | 显示真实浏览器画面，可点击、输入、按键、滚动；完成后继续同一运行，不重放前面的步骤 |

用户提供的 `fingerprint.go` / `herocore_profile.go` 已作为资料审阅：其中的稳定标识、画像字段、语言和时区映射可以帮助设计数据结构。这些文件只有画像数据与请求头生成，`Impersonate` 是目标名称，不能单独改变传输指纹；其中预设的硬件、WebGL 字符串及浏览器版本池没有被当成真实设备能力导入。本项目保存明确配置及实际执行值，不注入隐藏自动化特征的脚本，也没有集成 Sentinel / Turnstile 自动求解。国家或地区配置不表示实际出口位置。

浏览器执行需要额外安装 Node.js 20+、`scripts` 中锁定的 Playwright 依赖及对应浏览器。安装说明以 Chromium 为例；Firefox / WebKit 需要另装，缺少能力时会明确报错。仅构建现有 Go Docker 镜像不会自动具备这些依赖。完整安装、生命周期和验收命令见 [浏览器执行器说明](scripts/BROWSER_RUNTIME.md)。

## 当前原型

- 首次打开和刷新都保持空白，不加载测试包、上次 HAR 或历史项目。只有用户主动选择或拖入 HAR 才解析。主题与明确保存的模型设置可以保留。
- 默认白色主题，支持切换和记住深色偏好。导入后可描述操作目标，按页面、时间、域名、资源类型和关键词筛选。
- 默认「主流程分析」先将当前范围的紧凑请求目录交给 Agent，挑出关键请求，再详细解读选中项；目录筛选本身不创建方块，未选项仍为待分析，可能需要补充遗漏步骤。可切换「全部逐条分析」，或点击待分析记录单独补充。同一会话中已有有效说明的请求不会重复调用模型。
- 模型为详细分析的请求生成名称和用途说明。只有对应原 HAR、且名称和用途均非空的分析结果才会成为可用的请求方块；未分析、名称或说明不完整的请求不会补成占位方块；用途不确定时由 Agent 明确说明分析边界。
- 通过校验的分析结果分批自动加入画布，按业务分组折叠展示，展开可查看原始子请求与组内连线。Agent 返回的直接前序依赖会自动生成可编辑的「Agent 流程」草稿连线，包括数据依赖及有业务依据的执行顺序；有记录证据的关系标为「字段关联」。连线会去重并检查循环，不按纯时间相邻猜测顺序，也不会自动执行或改变步骤准备状态。
- 字段关联只有符合支持范围时才预填上游参数绑定；Agent 流程连线本身不会生成参数绑定，来源不明或不支持的编码仍需核对。用户改名、拖动或删除后不会被后续分析静默覆盖；需要主动恢复建议连线时点击「补齐连线」，它根据本次分析或项目中保存的依赖及录制字段证据补线。旧项目未保存的 Agent 依赖需重新分析，无法仅凭请求时间恢复。
- 辅助积木包括输入参数、字段提取、条件判断、人工输入、结果断言、输出，以及代理、画像、会话、浏览器操作、人工网页验证、循环、子流程与提前结束。参数向导支持固定值、用户填写、前序输出、运行时生成与人工输入；响应字段可用树形选择器选择。
- Agent 识别出的邮箱、用户名等普通业务资料直接显示为方块内的输入框，与运行准备共用填写值。输入位置必须对应真实存在的 JSON 字符串字段或单值查询参数；不会仅因方块名是登录或注册就添加邮箱。填完后可主动点击「已核对其余参数，标记就绪」，人工处理与暂不支持步骤仍保留各自条件。
- 画布工具栏支持「全屏画布」与「退出全屏」，也可按 Esc 返回工作台。查看运行准备或修补助手时会先退出画布全屏；浏览器不支持或未授予权限时显示原因。
- 「修补助手」把运行准备条件整理成少量业务问题、绑定草稿和逐步说明。用户在本页填写答案并主动应用，Agent 只能引用当前画布已有的可写字符串字段及经过录制证据核对的上游来源，不能覆盖已有绑定或生成任意代码。
- 配置用户自己的兼容 Chat Completions 的 API：地址以 `/v1` 结尾，调用 `/chat/completions`。
- 地址、模型和 API Key 使用明文输入。只有点击保存才保存到当前浏览器；可明确清除。项目导出不包含模型凭据。
- 导入、分析与自动生成不会执行请求；Agent 通过经过校验的画布命令编辑方块和连接，不能运行任意代码或命令。
- 分析使用后台任务与短轮询，避免网关长连接超时。详细解读首批最多 4 条、后续最多 12 条及约 96 KiB 顺序分批，支持停止和保留完成结果，不自动重试模型调用。正文使用前 4096 字节预览；跨批次共享全局目录、字段关系和已识别步骤。日志包含真实模型阶段、大小、耗时与关联编号，可导出，不记录 Key、Cookie 或 HAR 正文。主流程目录最多 1000 条、512 KiB，选中项最多 24 条；超限会明确提示缩小范围，不会静默忽略记录。
- 运行前预检定位具体节点与字段，选择入口后只执行可达流程，并使用不可变快照。真实服务器事件驱动绿色运行动画、计时、失败及跳过状态；断线后可继续观察同一任务，人工输入在原会话中暂停与继续。支持 `{{name}}` 与 `{{nodeId.body.field}}`。
- HTTP 4xx/5xx 默认失败，可配置接受范围；业务成功使用独立断言判断。画布最多 3000 节点和 5000 连接；每层执行图最多 100 个可达节点、300 条连接，结构化循环最多 1000 轮、嵌套 4 层，总执行步数最多 10000。任务限时 10 分钟（含人工暂停），完成结果保留 15 分钟。
- 导入、导出版本 4 的项目 JSON，包含多份录制、嵌套流程、资源关联、当前业务填写值及对话；版本 1–3 会迁移。默认导出移除代理账号和密码并标记待补充，可主动选择包含连接凭据。HAR 自带的请求头、正文和业务输入仍属于项目证据，导出前应自行检查。填写不会自动存入浏览器，刷新仍从空白工作台开始。
- 右键连线可以删除连线、删除前段或删除后段；菜单显示影响数量，工具栏支持撤销删除。前段包含连线起点及全部上游，保留终点；后段包含终点及全部下游，保留起点。共享节点的关联线也会移除。
- 每个积木右上角的垃圾桶可直接删除该积木，同时移除它的关联连线；工具栏的「撤销删除」可以恢复。也支持选中后按 Delete，或使用属性面板中的删除按钮。

空白页提供主动打开的无网络练习：输入参数 → 人工暂停 → 业务断言 → 输出结果。无需 HAR 或模型 API，可以体验正确输入与失败定位。已有项目通过“打开项目”主动恢复；`examples/condition-demo.json` 也可以导入。

## 使用修补助手

1. 打开「运行流程」查看准备条件，或直接打开下方「修补助手」。`REVIEW_REQUIRED` 表示仍需补充或核对资料，`UNSUPPORTED_STEP` 表示当前 HTTP 执行器无法完成该步骤；问题数量不等于待填写空格数量。
2. 点击「让 Agent 整理修补表单」。本次调用只发送节点说明、问题代码、已有字段位置和可用来源编号，不发送这些字段的值、完整请求或用户答案。可停止任务；停止不会应用草稿。
3. 在页面内填写 Agent 提出的业务问题，查看对应步骤和人工处理说明，再点击「填写并应用参数草稿」。答案进入当前页面的运行参数，与方块输入框和运行准备同步，不回传模型；主动导出项目时会随业务输入保存，重新打开该项目可恢复。
4. 应用草稿会保留原有准备状态。用户需逐步检查会话和参数，再对支持的步骤点击「我已核对这一步」；需要人工处理的步骤必须先安排人工输入。`unsupported` 不能通过修补助手确认成就绪，仍然阻止运行。
5. 点击「仅重新检查」，确认剩余条件后再主动启动运行。生成建议、填写答案、应用草稿、确认步骤和重新检查都不会执行 HAR。画布在生成建议后发生修改时，需要重新生成建议。

修补一次最多 100 个节点，每节点最多 80 个可用字段与 80 个来源，目录最多 512 KiB。模型最多提出 32 个问题、100 个绑定和 100 条步骤说明；这些是上限，不代表应填满技术参数。只有已有 JSON 字符串叶子字段、单值查询参数和允许写入的已有请求头进入候选；非 JSON 表单、数字/布尔动态字段、整段正文/地址替换、签名拼接与浏览器验证不在自动修补范围。没有足够证据时保留说明，由用户核对。

## 本地运行

需要 Go 1.26+ 和 Node.js 24+。

```powershell
cd web
npm install
npm run build
cd ..
go run ./cmd/server -addr 127.0.0.1:8090 -web web/dist
```

打开 `http://127.0.0.1:8090`。

仓库不附带真实 HAR，原始抓包文件不会进入 Git 或 Docker 构建。后端保留显式读取本地样例的兼容接口与 `-sample-har "完整路径"` 参数，前端初始化不调用它。

浏览器文件上传最多 256 MiB、10000 条原始记录。请求头与请求体保持完整；参考响应提供前 16 KiB 预览，完整响应通过随机导入编号按需读取，在服务器内存保留 30 分钟。最多保留三份导入，受总量限制时释放较旧记录；过期后重新导入即可。上传不写入服务器磁盘。非 HTTP 记录会跳过并显示提示。

开发前端时在另一个终端运行 `cd web; npm run dev`，Vite 会把 `/api` 转发到后端的 8090 端口。

## Docker

```sh
docker build -t har-canvas .
docker run --rm -p 127.0.0.1:8090:8090 har-canvas
```

可通过环境变量启用内置 HTTP BasicAuth。`HAR_CANVAS_USER` 和 `HAR_CANVAS_PASSWORD` 必须同时配置，只配置其中一个会启动失败；两者均未配置时维持本地无认证模式。认证覆盖网页、静态资源、健康检查、API 和默认 HAR 样例，浏览器首次访问时会提示输入账号密码。

```powershell
$env:HAR_CANVAS_USER = "your-user"
$env:HAR_CANVAS_PASSWORD = "your-password"
go run ./cmd/server -require-auth -addr 127.0.0.1:8090 -web web/dist
```

`-require-auth` 用来要求启动时必须存在有效认证凭据；不传此标志且未配置凭据时允许匿名使用。当前工作台保持用户选定的匿名访问方式。

Docker 可使用 `--env-file` 提供这两个变量。对外发布时使用平台提供的 HTTPS 入口，或由 HTTPS 终止服务转发到应用端口；BasicAuth 不加密 HTTP 连接中的凭据，不应通过公网明文 HTTP 使用。后端端口应只允许可信入口访问。

当前版本按单用户工作台设计，可以发出网络请求、显示 HAR 和模型凭据。上传 HAR 不会自动触发请求，也不会写入服务器磁盘；模型分析仅在点击分析时发出，所选请求会发送到用户配置的模型服务。

Instabox 的持久目录、systemd 安装与端口发布步骤见 [部署说明](deploy/README.md)。公网验收可设置 `HAR_CANVAS_URL` 后运行 `node scripts/verify-deployment.mjs`；认证读取忽略的 `.deployment/service.env`，可用 `HAR_CANVAS_ENV_FILE` 指定其他文件。额外设置 `HAR_CANVAS_VERIFY_EXAMPLE=1` 可验证默认测试包和完整响应读取，不会回放抓包请求。

## 运行约束

- HAR 是一次网络观察记录，不保证包含动态签名、Token 生成、页面脚本等全部逻辑。
- HTTP 重放与普通浏览器操作是两种执行方式；浏览器需要安装对应执行环境。需要人工网页操作时使用「打开浏览器完成验证」暂停并接管，当前不会自动处理网站挑战。弹窗与下载暂未开放。
- 运行器阻止访问服务器内网、回环和链路本地地址，检查 DNS、重定向，并限制请求时间和响应大小。
- 模型输出只作为结构化建议处理，不能运行任意代码或命令。
- Cookie 和 Token 可能过期。实际发起请求前应检查目标、参数和凭据。
- 第一版提供流程项目导出；还没有独立 Go/JS 程序导出。
- 条件的 `exists` 表示变量存在且不是 `null`，空字符串也算存在。多条分支汇合时，任一有效分支可达就会执行汇合节点；运行器会先等待所有前驱处理完毕。重复使用结构化循环内部画布，每层仍是无环图，不通过向前回连普通执行线构造循环。

## 验证

```sh
go test ./...
cd web
npm run build
npm run test:graph
npm run test:agent
npm run test:blocks
```

启动后端后，还可以在项目根目录运行 `node scripts/smoke.mjs`。它通过本地模拟模型接口验证 `/v1/chat/completions`，不需要真实 Key，也不访问外部目标。

新增 `npm test` 运行全部前端单元测试。`node scripts/smoke-runtime.mjs` 自行启动隔离模拟服务，实际等待超过 20 秒的模型响应，并覆盖分析不重放、人工暂停、断言、HTTP 失败、增量事件和结构化预检，不需要真实 Key。真实 HAR 验收只进行导入与授权的模型分析，不执行抓包中的注册请求。当前 Windows 环境未运行 race 检测，Docker 镜像未实测。
